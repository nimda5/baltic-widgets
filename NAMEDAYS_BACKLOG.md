## How to work through the backlog

Continue research in the shared branch `codex/namedays-round4`; do not create a separate branch per round.

1. Work in calendar order: take the next day needing a research pass from Priority 0 and examine its names in all three countries before the later priority lists. Explicitly unverified hypotheses remain open in this backlog and the date queue while the pass advances; do not call those days verified-complete. Work in name families only when sources establish the relationship and the same text is true for every spelling.
2. Read [NAMEDAYS_SOURCES.md](NAMEDAYS_SOURCES.md) before searching. Extend its resource directory when a useful source is found, and record source IDs and precise pages in the next numeric round notes. Verify factual claims in sources you actually opened. An unverified working hypothesis may be displayed only with an explicit translated Hypothesis label and qualified wording; retain status needs_more, verification_status unverified, its source basis and a concrete next step in the round notes. Never count it as a reviewed history. Keep URLs in research files and provenance metadata only, never as widget citations. Useful sources: izpetnieks.lv (Klāvs Siliņš dictionary pages), behindthename.com, enciklopedija.lv, literatura.lv, vle.lt, et.wikipedia.org, eki.ee, national libraries and museums. vardai.vlkk.lt blocks automated requests; open it manually.
3. Write two paragraphs per language (lv, ru, en, lt, et): origin and how the name reached the Baltic languages, then one concrete, verified historical detail. Keep uncertain etymology explicitly uncertain; describe literary events as literature; never call a calendar or publication year the creation date unless a source says the name was coined then.
4. Add the entry to a `public/namedays-history-r<round>-<topic>.js` module, import it in `public/namedays-history.js`, record every examined name (including skipped ones) in `research/namedays/round<round>-notes.json`, bump `WRITER_VERSION`, then run `node scripts/generate-namedays.mjs --country=lv` for LV-only work (use `lt` or `ee` for another country; omit the flag only for a full rebuild), `node --test parsers/namedays.test.mjs` and this script.

## Known data issues

- LT calendar: the supplied misspellings Arnasd, Felidta and Binifacas are corrected to Arnas, Felicita and Bonifacas through `CALENDAR_CORRECTIONS` in `parsers/namedays.mjs`; only the corrected forms are in the official VLKK registry. Check whether Arnas really belongs on 13 August: tv3.lt lists 8 July, and day.lt lists no Arnas for 13 August.
- LT calendar: nine names had leading or trailing spaces in the published file. The generator now normalizes whitespace and the validator rejects padded names.
- LV: `Asnate` and `Asnāte` are separate calendar spellings with the same registered count; check whether the registry merges them.
- LV calendar pairs that share a day but are unrelated names (for example Brenda and Brendons) must not be merged into one family.
- Name days for the same name differ between countries (for example Ieva/Eva, Matīss/Mati). Texts must not assume one shared date.
